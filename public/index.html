Git Pre-Commit Hook Integration

Intercept and block secrets directly inside your local developer terminal before commits are finalized.

Pre-Commit Security Interception Lifecycle
Developer writes code
→
git commit
→
GitPulse Scanner
→
Secret Found → ⛔ BLOCK COMMIT (Exit 1)
Clean Diff → ✅ ALLOW COMMIT (Exit 0)
Option A: Framework Config (.pre-commit-config.yaml) 
repos:
  - repo: local
    hooks:
      - id: gitpulse-interceptor
        name: GitPulse Secret Interceptor
        entry: py -m gitpulse.cli --staged
        language: system
        stages: [commit]
Option B: Native Hook Script (.git/hooks/pre-commit) 
#!/bin/sh
# GitPulse Pre-Commit Hook
echo "🛡️ GitPulse: Scanning staged changes..."
py -m gitpulse.cli --staged
EXIT_CODE=$?
if [ $EXIT_CODE -ne 0 ]; then
    echo "❌ COMMIT BLOCKED: Secret(s) detected!"
    exit 1
fi
exit 0

Multi-Factor Secret Detection Architecture

Combining three independent detection heuristics to eliminate false positives and catch zero-day credentials.

1. Regex Pattern Engine

Curated signatures for AWS Access Keys, OpenAI project keys, GitHub PATs, Stripe tokens, Slack webhooks, and private encryption headers.

Weight: 40% Confidence
2. Shannon Entropy Engine

Calculates information density $H(X) = -\sum P(x) \log_2 P(x)$. Character diversity thresholds flag high-randomness hex and base64 strings.

Weight: 35% Confidence
3. Variable Context Analysis

Examines assignment operands (`api_key`, `password`, `secret`, `token`, `cred`) to discern credentials from ordinary strings.

Weight: 25% Confidence

Security & Privacy Commitment

GitPulse is engineered for privacy and security. When using this web demonstration, code snippets are inspected purely in-memory within isolated serverless invocations and are never saved to disk or persistent storage. Never submit actual production keys or confidential customer credentials to any public web demonstration. All sample credentials included in GitPulse presets are synthetic mock credentials.
